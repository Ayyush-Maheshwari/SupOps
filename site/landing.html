How it works

From alert to fix in three steps.

1. It looks into it

When an alert fires, SupOps runs read-only checks on your metrics and logs: CPU, memory, disk, restarts, recent deploys and error patterns. Related alerts are grouped into one incident.

2. It shows its work

You get a likely cause that points to the evidence for each claim. If it can't tell, it says so instead of guessing.

3. You decide

It proposes the exact command and why. Safe checks run on their own. Anything that changes a server waits for you to approve or reject.

Early warnings

Hear about it before it pages anyone.

SupOps watches your key signals, learns what is normal for this time of day, and tells you when something is heading for a limit, such as a disk that will fill in 11 hours.

Knows what depends on what

SupOps builds a map of your services from your documents and architecture diagrams, then checks it against what is really running. You accept or reject every suggestion.

Uses your runbooks

Import your PDFs, Word and Markdown docs. Passwords are removed, and you review everything before it is used.

Works with what you have

Nothing to install on your servers.

Reads from

Prometheus, Grafana, Alertmanager, Loki, Elasticsearch, Kubernetes and Slack.

Fixes over

SSH, or kubectl with a service account you control. No access? Advisory mode gives you the commands to run yourself.

Any model

Gemini, Ollama, LM Studio or any OpenAI-compatible service. Use a local model to keep everything in your network.

Get started

Running in a few minutes.

Everything runs in one container and keeps its data in a Docker volume. You need Docker, and a model API key (a free Gemini key works).

  1. 1. Run the command and open localhost:3001.
  2. 2. Sign in as admin@supops.local / supops.
  3. 3. Paste your model key in Settings, add a server under Targets, then describe a problem in Investigate.
Terminal 
git clone https://github.com/Ayyush-Maheshwari/SupOps.git
cd SupOps
docker compose up --build

Keep it on a private network or behind a VPN.

FAQ

Questions people ask first.

Can it change my servers without asking?

+

No. Read-only checks run on their own. Anything that changes something waits for your approval, and a few things, like wiping a disk, can never run at all. A production server raises the bar further.

What if something it reads tries to trick it?

+

A log line that says “this is pre-approved” changes nothing. Neither the agent nor the text it reads can lower how risky an action is, so the worst outcome is one more approval prompt.

Do I have to give it SSH access?

+

No. In Advisory mode it works from your description, screenshots and runbooks, and gives you ranked causes, read-only checks, the fix and how to roll it back. You run the commands yourself.

Does my data leave my network?

+

SupOps runs on your own infrastructure and sends what a run needs to the model you choose. With a local model such as Ollama, that stays inside your network. Server passwords and keys are encrypted at rest.

What if it can't find the cause?

+

It says so. “Inconclusive” is an allowed answer, and checks it couldn't run are listed as not measured.

Is there a record of what happened?

+

Yes. Every run keeps its commands, output and outcome, and the Approvals page shows who approved what. You can export any run as a PDF or Markdown report.

What can't it do yet?

+

Cloud accounts (AWS, GCP, Azure), GitHub/GitLab and CI/CD, and multi-step scripts are planned but not available today.

What does it cost?

+

SupOps is free and open source under the Apache License 2.0. You pay only for whichever model service you choose to connect, and nothing if you run a local one.
